Métodos de Pago por URL Separada

Integración de PayIn usando un enlace de checkout por cada método de pago. Puedes redirigir a tu cliente al checkout completo o renderizar tus propios botones a partir del array methods que devuelve la API.

Flujo General

1

Crear un PayIn

Llama a POST /api/payin/register con los datos del cliente, la moneda y el monto. La API devuelve un checkoutUrl y un array methods con una URL por método.

2

Elige cómo mostrar los métodos

Opción A: redirige al cliente a checkoutUrl. Opción B: renderiza tus propios botones usando methods[].

3

El cliente paga

Cada URL de methods[] lleva al checkout de ese método específico. Si el cliente paga antes de dueDate, el estado de la transacción cambia automáticamente.

4

Consulta el estado

Verifica el estado del PayIn por referencia o por tu customId, o recibe la notificación por webhook.

¿Y si methods viene vacío?

Los métodos disponibles dependen de la configuración de tu cuenta y del país. Si methods viene vacío, contacta a soporte para habilitar los métodos de pago.

El Sandbox es único y compartido por todos los países para desarrollo y pruebas.

Notas importantes

  • CORS: si usas JavaScript desde el navegador, tu dominio debe estar habilitado en la whitelist de CORS del backend.
  • Webhooks: JavaCash puede notificarte automáticamente cuando cambia el estado de un PayIn. Consulta la documentación de Webhooks para configurar las URLs de notificación.
  • Expiración: si el cliente no paga antes de dueDate, el link de checkout deja de funcionar y el estado pasa a failed.
  • Monedas permitidas: cada país tiene sus monedas habilitadas. Si envías una moneda no permitida, la API retornará un error 400.
